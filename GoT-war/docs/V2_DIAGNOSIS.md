# Version 1 diagnosis before scaling

The original campaign is preserved at commit `b8721e5f4c24915605b3192239d9cc1e1e4801d4`, in its original result paths and in the local snapshot recorded by `configs/versions.json`. Version 2 writes to separate paths. The numerical audit is `results/v2/v1_diagnosis.json`.

| Observation | Verified implementation cause | Scientific consequence | Version 2 correction |
| --- | --- | --- | --- |
| All 30 incomplete SCMs hide only the final outcome equation | `benchmark.generate` scans eligible nodes in reverse order and accepts the first ambiguity; the outcome always qualifies | No evaluation of missing intermediate or multiple mechanisms | Predeclare four omission conditions, independently draw DAGs, audit family coverage before test inference |
| All 43 identified incomplete-test structural questions preserve the factual outcome; 47 are ambiguous | One unknown final rule constrained by its factual row, combined with the fixed query policy | Factual carry-forward is perfect on the identified incomplete subset | Include it as a baseline; evaluate changed/preserved outcomes separately and include internal omissions and both factual states |
| P is a restricted uncertainty solver | `experiments.execute_answers` exhausts tables only for exactly one unknown, two-parent Boolean node; its query score excludes explanation/source ranking | Its score cannot validate the full explanation system | General bounded compatible families; report intervention, grounding, ranking, explanation and reviewer metrics separately |
| All four retained application games are unanimity games | Exact re-execution gives 63 zero coalitions and one positive coalition for each six-path model, and 3 zero/1 positive for the two-path model | Equal shares are a consequence of the assumed conjunctions, not discovered relative importance | Publish coalition distributions, substitute/joint/inhibitory behavior, references and path-selection sensitivity; never select for unequal shares |
| Every path has weakest-link support zero | `application.assess_edges` asks for evidence for the entire mechanism while warning that events do not identify functional form; unsupported/unassessed edges are correctly zeroed later | Directional evidence and equation identification are not separately inspectable; the resulting ranking is unavailable | Independently assess event support, directional influence and exact-function identification on contextual passages; unsupported directions remain zero |
| One distinct function per case | Repeated local generations retained the same behavior; fixed parents, all-parent active dependence, no internal backgrounds and hard factual matching constrain revision | Generation count is not model uncertainty coverage | Inspect local truth tables; allow source-justified representation revisions and explicit constrained backgrounds; deduplicate by behavior and intervention outcomes |
| Prose generation and reviewing fail | Prose prompt includes literal placeholder `baseline OR full`; reviewer invents verbatim quotes and sentence decomposition | Explanation failure and reviewer failure are conflated | Compute a structured record first, assign sentence IDs before review, validate reviewer coverage and references, separate deterministic and semantic verdicts |
| Equation descriptions disagree with behavior | Local validation checks typed execution and factual matching, but stores free-form descriptions without a behavioral entailment check | For example, the Daenerys AND rule calls one input sufficient while making both necessary; its assumptions also describe proceeding despite the other input | Derive behavior summaries from exhaustive finite tables/bounded probes and review prose against those summaries; no researcher-written story correction |
| A null process birth can make a registered job uncontrollable | `Budget.launch` records `process_birth` without checking it; `stop_owned` appropriately refuses null identities | The supervision test can fail and cleanup can miss the project job | Bounded identity retries before registration; explicit launch failure and direct-child cleanup on exhaustion; verify on the GPU host |

The retained version 1 process registry contains **zero** null births. The code admits the reported failure condition; this is distinct from claiming it occurred in the recorded production campaign. Fault-injection tests exercise transient and persistent identity failures. The safety rule against signaling an unverified group is preserved.

The evidence diagnosis does **not** establish that any formerly unsupported edge deserves support. Version 2 must assess contextual evidence afresh and retain unsupported connections as such. A more detailed transcript also remains a transcription of a fictional episode, not an independent observation of a counterfactual law. Source judgments need researcher adjudication.
