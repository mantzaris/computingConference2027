# Phase-two decisions

- Use the new user prompt as the specification: no separate design text exists.
- Preserve all historical source, metrics, claims, configurations and figures.
  New source is sem_update.phase2; reports/configuration are under phase2/;
  operational evidence is under .artifacts/phase2/.
- Copy the completed historical SQLite ledger into the phase-two artifact root
  and append only phase2-prefixed jobs. Its cap is historical use + 16 hours,
  bounded by the original 64-hour cumulative ceiling. Old ledger/logs remain
  untouched. HF weights and pinned DCDI source are reused without downloads.
- Retain the existing conditional-flow architecture, losses, canonical parent
  cache keys, graph operations and diagnostic scheduling. Remove audit access
  from bank construction; calibrate selection only after bank immutability.
- The robust score allocates the shared observational NLL and edge penalty to
  every intervention score; intervention node losses use inverse intact-role
  counts, ensuring the mean reconstructs the historical selection objective.
- Audit uses whole-joint truncated log density divided by the number of intact
  nodes, then averages environments equally for every single/mixture method.
  Mixture logsumexp occurs before that division. The same historical W1/NLL
  audit thresholds are retained. This normalization change is explicit.
- Full candidate-bank construction is charged logically to M3/M4/M5 and their
  controls; actual shared-cache execution is recorded separately. Candidate
  counts will not be called equal achieved compute.
- Validate official DCDI-DSF CUDA behavior on development tasks before choosing
  M2. A failure is an implementation/coverage problem, not poor-method evidence.
- Fix the LLM full-graph/edit-command ambiguity with explicit legal edit IDs,
  uniformly V-prefixed graph IDs and search-only feedback. Actual local model
  selections from this menu are recorded; no inferred or fabricated proposals.
- Preserve the unused polarizer mid/strong regimes as a distinct new-regime
  real panel. RGB follow-up remains exploratory. The apparatus and design were
  already familiar; this is not fresh independent-apparatus confirmation.
- Logged motor setpoints differ from the documented 0.1-degree grid. Condition
  polarizer predictions on recorded assignment values, with identical target
  draws across methods, and disclose this conditional-design estimand.
- Initial correctness launch: 19 passed, 18 temporary-directory setup errors.
  After creating the test parent directory, all 37 tests passed, including
  official DCDI-DSF CPU/CUDA density and gradient equivalence. No main outcomes
  informed this harness repair.
- Ridge alpha 0.1 was selected by average search score on three separate
  development systems, from the prespecified four-value grid. The final-test
  partitions were unavailable to this choice.
- Both complete five-node pilots ran: 922.640 and 1069.259 device seconds.
  Their DCDI-DSF fits hit 40,000 steps at normalized h=1.8669e-7 and 2.3681e-8,
  respectively, close to but above the strict 1e-8 threshold. Increase the
  **main** prespecified DCDI ceiling to 60,000, keeping earlier pilot records
  and source archived. This decision uses convergence and runtime, not final
  prediction rankings. The original pilot configuration is retained separately.
- Use three controlled-dataset workers on the existing device (48 available
  CPUs), with LLM stages separated. Pilot utilization was roughly 8–11 percent
  for a single DCDI worker. This preserves the original fitting algorithm while
  keeping the complete matrix inside the 16-hour additional cap. Canonical
  fitting times include concurrent execution contention and are disclosed as
  measured reservation time, not isolated kernel benchmarks.
- Do not expand to ten nodes: measured artifact growth, only 1.42 GB local free
  space, and unverified persistent Pod storage make durable preservation of an
  expanded matrix uncertain. Preserve all 15 controlled SCMs, five semantic
  SCMs, all six methods and the real case before optional graph sizes.
- The corrected actual Qwen3-8B development path produced six valid new edits,
  five score rejections and one accepted search change, with no malformed,
  invalid-node, cyclic or duplicate proposals. This validates the interface;
  it is not a main-benchmark performance result.
- Tighten phase-two cache isolation before the main freeze: mechanism identity
  hashes only fit/early values; banks additionally hash search; selection hashes
  calibration/audit separately. A regression test verifies that changing held-
  out calibration/audit values cannot change a mechanism initialization seed.
  The pilot prototype inherited the historical full-archive fingerprint; its
  original source/data/results remain preserved and are development-only.
- Real preparation now reads only pre-test CSV prefixes. Training-only raw and
  residual autocorrelations, fixed measurement settings and block boundaries
  are recorded before any new-regime final outcomes are opened.

  weights <=1e-10 while audit logsumexp retained them. Tiny positive components
  can materially affect tail likelihood. Preserve every strictly positive
  weight in both paths; add an explicit tail-density regression test. No main
  calibration/audit choices or final outcomes existed at discovery of this
  issue. Three running discovery jobs were interrupted with their checkpoints
  retained and resumed using the same seeds and optimizer states. Their failed
  attempts, logs and device intervals remain evidence. Actual incremental job
  costs now include all earlier closed attempts. The original protocol is
  archived; data, splits, hyperparameters and fitting policy did not change.
